# Bulk credit transfers with VoP

<p className="ia-lede">For bulk <Term id="credit-transfer">credit transfers</Term>, whether a verification token is required depends on the account type and an account-level setting. Company accounts can opt in or out; individual accounts always require verification.</p>

:::info Requirements
Bulk credit transfers require [custom verification](/payments/concepts/verification-of-payee/integration-options#option-2) using the [`verifyBeneficiary`](/payments/guides/credit-transfers/sepa/verify-beneficiary) mutation. The default verification flow doesn't support bulk payments.
:::

## VoP requirements for bulk transfers {#bulk-requirements}

Under the [European Instant Payments Regulation (IPR)](https://eur-lex.europa.eu/legal-content/EN/TXT/HTML/?uri=OJ:L_202400886), payers that are not consumers and submit multiple payment orders can opt out from verification services during their contractual relationship with their PSP.

This regulatory framework allows Swan to offer different default VoP requirements based on account type:

<FieldRequirementsLegend />

| Account type | Default token requirement | Can change setting | Consent requirements |
| --- | :---: | :---: | --- |
| **Company** | <Opt /> | <Yes /> | **Opted in**: No consent required.<br/>**Opted out**: User consent required via [SCA](/users/concepts/consent/sca). |
| **Individual** | <Req /> | <No /> | Cannot change settings |

:::note Why these defaults?
- Swan opts out company accounts by default to accelerate bulk file processing and reduce friction in high-volume business flows.
- When multiple company accounts exist for the same <Term id="account-holder">account holder</Term>, all accounts are opted out by default regardless of any previous account settings.
:::

## Account-level verification settings {#account-settings}

Individual accounts always require tokens: bulk transfers without them are rejected. Company account holders can opt in or out.

### Changing VoP settings {#changing-settings}

Company account holders change the setting with the `updateAccountSettings` mutation. The user needs the `canViewAccount` and `canInitiatePayments` permissions and an `Enabled` account membership; the consent required for each direction is in the table above.

The [guide to update VoP settings for bulk transfers](/payments/guides/credit-transfers/sepa/update-vop-settings) shows the mutation, its parameters, both success payloads, the rejections, the webhook, and Sandbox behavior.

:::warning Integration requirement
You must implement the `updateAccountSettings` mutation for company account holders to opt in or out themselves. Without it, they must go through Swan's [support request form](https://support.swan.io/hc/en-150), which adds delay.
:::

## Preparing for disputes {#dispute-preparation}

Swan logs all VoP setting changes and verification history for dispute protection. These logs aren't currently available through the API, so record these changes in your own systems. This audit trail helps determine liability if an end-user disputes a payment to the wrong beneficiary.

The `AccountSetting.Updated` [webhook](/payments/guides/credit-transfers/sepa/update-vop-settings#webhook-notifications) notifies you each time the setting changes, whether by the user or by a Swan agent after a support request.
