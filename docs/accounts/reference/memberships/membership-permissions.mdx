# Membership permissions

This reference details every <Term id="account-membership">account membership</Term> permission and how the `canManageCards` and `canManageAccountMembership` permissions interact.
For how permissions are granted and memberships with no permissions, see the [permissions concept](/accounts/concepts/memberships/permissions).

## Permissions {#permissions}

| Permission | Account member can... |
| --- | --- |
| `canViewAccount` | View the account and some information about the account, including but not limited to: main and virtual [IBANs](/accounts/concepts/ibans), [trusted beneficiaries](/payments/concepts/credit-transfers/#beneficiaries), [payment mandates](/payments/concepts/direct-debit/#mandates), and [transactions and transaction details](/payments/concepts/transactions#transactions). |
| `canManageBeneficiaries` | Add or remove [beneficiaries](/payments/concepts/credit-transfers/#beneficiaries), and save beneficiaries as trusted. |
| `canInitiatePayments` | [Initiate (send) credit transfers](/payments/concepts/credit-transfers/) to trusted beneficiaries. |
| `canManageAccountMembership` | Add, update, suspend, resume, and disable account memberships, and view the list of account members. |
| `canManageCards` | View, add, and update their own cards and [cards for account memberships](/cards/concepts/card-formats#cards-account-memberships) they manage. |

## Managing cards {#permissions-cards}

Whether your **account members can manage cards** and **for whom** depends on both `canManageAccountMembership` and `canManageCards` permissions.
Cardholders without the `canViewAccount` permission can view their own transaction history, even if they have no other permissions.
