# Update account holder information

Update an existing <Term id="account-holder">account holder</Term>'s `vatNumber` and `taxIdentificationNumber` after onboarding with the `updateAccountHolder` mutation.
Use it to correct or add tax details once the account holder already exists.

:::tip Prerequisites
You need a [project access token](/build/using-api/authentication#tokens-project) to call this mutation.
Use the access token and the [endpoint](/build#endpoints) of the environment you're working in, Sandbox or Live.
:::

:::note Separate from onboarding updates
This mutation is separate from the onboarding update mutations `updateCompanyAccountHolderOnboarding` and `updateIndividualAccountHolderOnboarding`.
Use it after the account holder is created and verified, not while an onboarding is still in progress.
:::

## Guide {#guide}

1. [Get the account holder ID](#get-id) of the account holder you want to update.
1. Call the `updateAccountHolder` mutation with your project access token in the `Authorization` header (`Bearer $YOUR_ACCESS_TOKEN`).
1. Add the `accountHolderId` from step 1, then the fields you want to change (lines 4-6).
1. Add the success payload (lines 9-21).
1. Add the rejection members to handle errors (lines 22-34).

```graphql {4-6,9-21,22-34} showLineNumbers
mutation UpdateAccountHolder {
  updateAccountHolder(
    input: {
      accountHolderId: "$YOUR_ACCOUNT_HOLDER_ID"
      vatNumber: "$YOUR_VAT_NUMBER"
      taxIdentificationNumber: "$YOUR_TAX_ID_NUMBER"
    }
  ) {
    ... on UpdateAccountHolderSuccessPayload {
      __typename
      accountHolder {
        id
        updatedDate
        info {
          ... on AccountHolderCompanyInfo {
            vatNumber
            taxIdentificationNumber
          }
        }
      }
    }
    ... on AccountHolderNotFoundRejection {
      __typename
      message
    }
    ... on ValidationRejection {
      __typename
      message
      fields {
        code
        message
        path
      }
    }
  }
}
```

:::info VAT numbers apply to companies
`vatNumber` is available only on company account holders (`AccountHolderCompanyInfo`).
Individual account holders have a `taxIdentificationNumber` but no VAT number.
:::

## Payload {#payload}

A successful response returns `UpdateAccountHolderSuccessPayload` with the updated values, which confirms the change was applied.

```json showLineNumbers
{
  "data": {
    "updateAccountHolder": {
      "__typename": "UpdateAccountHolderSuccessPayload",
      "accountHolder": {
        "id": "$YOUR_ACCOUNT_HOLDER_ID",
        "updatedDate": "2026-06-01T09:35:46.673Z",
        "info": {
          "vatNumber": "FR40303265045",
          "taxIdentificationNumber": "30 23 417 612 814"
        }
      }
    }
  }
}
```

## Country requirements {#country-requirements}

Which countries require `vatNumber` and `taxIdentificationNumber` is determined at onboarding, and depends on the account holder's country and type.
For company account holders, `vatNumber` is required only for Italy at onboarding, and is optional elsewhere.
For the full per-country rules, see the [company onboarding fields](/accounts/reference/onboarding/company-onboarding-fields) and [individual onboarding fields](/accounts/reference/onboarding/individual-onboarding-fields) pages.

## Rejections {#rejections}

| Rejection | Cause | Solution |
| --- | --- | --- |
| `AccountHolderNotFoundRejection` | No account holder matches the `accountHolderId` you passed. | Check the ID from step 1 and confirm it belongs to your project. |
| `ValidationRejection` | One or more input values are invalid, such as a value that's too long. Swan doesn't check the format of `vatNumber` or `taxIdentificationNumber`, so make sure you send valid values. | Read the `fields` array in the response. Each entry has `code`, `message`, and `path` identifying the specific validation error. Correct the flagged field and retry. |
