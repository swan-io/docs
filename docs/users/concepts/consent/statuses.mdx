# Consent statuses

The lifecycle of a <Term id="consent">consent</Term> request, from creation through to a final status.

## Statuses {#consent-statuses}

```mermaid
%%{ init: { 'flowchart': { 'curve': 'linear' } } }%%
flowchart LR
    SOI((Sensitive<br/>operation initiated)) -.-> C[Created]
    C -.-> S[Started]
    C -.-> CD[Canceled]
    S -.-> CD
    S -.-> OC[OperationCommitting]
    OC --> A[Accepted]
    S -.-> CR[CustomerRefused]
    S -.-> E[Expired]
    OC -.-> FA[Failed]
    subgraph V[Valid consent]
        A
    end
    subgraph F[Final status]
        CD
        CR
        E
        FA
        V
    end
    style SOI fill:#D4D3D5,stroke:#514F59
    style F fill:#fffdf4,stroke:#cca922
    style V fill:#dfedf2,stroke:#4d8296,stroke-width:3px
    style CD fill:#f6ddcc,stroke:#c12236
```

| Consent status | Explanation |
|---|---|
| `Created` | A sensitive operation was initiated, triggering the creation of a consent request automatically. The user who needs to consent hasn't opened the consent URL yet.<br /><br />**Next steps**:<ul><li>When the user opens the consent URL, the status moves to `Started`.</li><li>If the consent is canceled, the status moves to `Canceled`.</li></ul> |
| `Started` | The user opened the consent URL but hasn't consented yet.<br /><br />**Next steps**:<ul><li>If the user consents successfully, the status moves to `OperationCommitting`.</li><li>If the user refuses to consent, the status moves to `CustomerRefused`.</li><li>If the user doesn't consent within the validity window, the status moves to `Expired`.</li><li>If the consent is canceled, the status moves to `Canceled`.</li></ul> |
| `Accepted` | The user consented successfully. |
| `Canceled` | Consent requests can be `Canceled` by you or your user as long as the consent has the status `Created` or `Started`. `Canceled` also applies to child consents when a preceding child consent `Failed`. Canceling a parent multi-consent also cancels all its child consents. |
| `CustomerRefused` | The user refused to consent to the sensitive operation. |
| `Expired` | The user opened the consent URL, but didn't consent within the 20-minute validity window. This also applies if the user tries to consent but can't manage to complete a valid consent within the 20 minutes. When a parent multi-consent expires, all its child consents also expire. |
| `OperationCommitting` | The user consented, and the operation is committing. For a multi-consent, one or more child consents are still in progress.<br /><br />**Next steps**:<ul><li>If the operation completes, the status moves to `Accepted`. For a multi-consent, this means all child consents have the status `Accepted`.</li><li>If a technical error occurs during execution, the status moves to `Failed`. For a multi-consent, this means a single child consent has the status `Failed`.</li></ul> |
| `Failed` | The user successfully accepted the consent, but a technical error occurred during execution. As a result, the operation didn't complete, and the user must retry.<br /><br />For multi-consents, this status means a child consent `Failed`. Any child consents already `Accepted` remain valid, while unexecuted child consents are `Canceled`. |

The `ConsentStatus` enum also includes `CredentialRefused`, which is deprecated and no longer supported.

:::info Child consent restrictions
You can't change the status of a child consent directly. 
To update a child consent, you must update the parent [multi-consent](/users/concepts/consent#multi-consent). 
:::
