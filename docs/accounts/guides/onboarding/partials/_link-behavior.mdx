- Unique onboarding links are single-use. Once an onboarding is finalized, submitting its link again returns an `OnboardingAlreadyFinalizedRejection` on the `finalizeAccountHolderOnboarding` mutation (not an HTTP 500). Handle this rejection instead of retrying, then generate a new link to start a new onboarding.
- The true purpose of the `state` parameter is to prevent Cross-Site Request Forgery (CSRF) and related attacks. Consider using it to your advantage. It includes your user's onboarding ID by default, so you can save this onboarding ID when generating the link.
