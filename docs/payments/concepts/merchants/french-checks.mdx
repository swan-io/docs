# French checks for merchants

<p className="ia-lede">Accept French checks as a <Term id="merchants">merchant</Term>: eligible banks, the fields to declare, check <Term id="transactions">transactions</Term>, cancelation, settlement, FNCI verification, and <Term id="r-transaction">R-transactions</Term>.</p>

## About French checks for merchants {#about}

Merchants can accept <Term id="payments">payments</Term> using French checks if the debtor's bank is located in **mainland France** and the following **territories**: Guadeloupe, French Guiana, Martinique, Mayotte, Reunion, Saint Martin, and Saint Barthelemy.
New Caledonia, French Polynesia, and Wallis and Futuna aren't currently supported.

Checks must be **unique**: a different CMC7 code and RLMC key for each check.

:::caution Beneficiary name
The beneficiary name on the check must match the **account holder name** or the **<Term id="merchant-profile">merchant profile</Term> name** exactly.
If these do not match, the check will be rejected with one of the following reasons: `BeneficiaryMismatch` or `BeneficiaryMissingOrIncorrect`.

:::

On the **back of the check**, the merchant must write their Swan account number as well as provide their signature.


## Required API fields {#fields}

When declaring checks with the API, there are five mandatory API fields:

1. `amount`: monetary amount of the check (can't exceed €10,000).
1. `currency`: `EUR` (only euros are supported).
1. `CMC7` (Caractères Magnétiques Codés à 7 bâtonnets): 31-digit code composed of 3 series of numbers.
    - Series 1: check number; 7 digits
    - Series 2: interbank codes; 12 digits
    - Series 3: account number; 12 digits
1. `rlmcKey` (Recomposition de la Ligne Magnétique du Chèque): 2-digit code calculated based on the CMC7.
1. `merchantProfileId`: the merchant profile's ID.


## Merchant check payments {#payments}

Merchant check payments follow the shared [merchant payment object](/payments/concepts/merchants/payments#object).

### Check transaction types {#payments-transaction-types}

There are **two transaction types** for merchant check payments.

| Transaction type | Explanation | Impacted [account balance](/accounts/concepts/account/balances) |
| :--- | :--- | :--- |
| `CheckIn`        | Captured payment that first impacts the merchant's `Upcoming` balance, and then their `Booked` balance. | `Upcoming`<br />`Booked`   |
| `CheckInReturn`  | Disputed payment that immediately impacts the merchant's `Booked` balance.                           | `Booked`                 |

### Payment object statuses {#payments-statuses}

Checks never use `Authorized` and can't be refunded (see the [statuses by payment method](/payments/concepts/merchants/statuses#payments-statuses-by-method)). What each status means for a check:

| Check payment object status | Explanation |
|---|---|
| `Initiated` | Merchant submitted the check information to Swan, but the check hasn't been processed yet. |
| `Captured` | Check was accepted and funds were made available in the merchant's account. This can be a final status if the customer doesn't dispute the payment. |
| `Rejected` | Swan's check provider rejected the check; it's [mailed back](#rejected) to the merchant. |
| `Canceled` | The merchant canceled the check before Swan's check provider received it. A canceled check that still arrives is rejected with `CheckReceivedLate` and mailed back. |
| `Disputed` | The customer disputed the payment or their bank returned it after capture, for example for insufficient funds. |

### Payment object balances {#payments-balances}

The [payment object balances](/payments/concepts/merchants/payments#balances) behave as follows for checks. `totalAuthorized`, `availableToCapture`, `availableToRefund`, and `totalRefunded` are always zero: checks aren't authorized, captured manually, or refunded.

| Check payment object balance | Explanation |
|---|---|
| `availableToCancel` | Use this balance to verify whether the payment can be [canceled](#canceling). |
| `totalCaptured` | The full payment amount, once the check is processed. |
| `totalDisputed` | The amount disputed by the customer or returned by their bank. |


## Rolling reserve {#rolling-reserve}

[Rolling reserve](/payments/concepts/merchants/payments#rolling-reserve) applies to French checks: by default, 100% of the payment over 10 interbank business days.

## Payment amount limit {#payment-limit}

Swan may apply a [payment amount limit](/payments/concepts/merchants/payments#payment-limit) to a single check payment. If a payment exceeds this limit, the API returns a `ForbiddenRejection` error. To query the limit, use the `paymentAmountLimit` field at the `merchantPaymentMethod` level when you [request the payment method](/payments/guides/merchants/in-person/checks/request).

## Canceling payments {#canceling}

Merchants can cancel check payments using the [`cancelMerchantPayment`](https://api-reference.swan.io/mutations/cancel-merchant-payment/) mutation.
To understand if a payment is cancelable, check its `availableToCancel` balance.
Only the full amount can be canceled.

Checks can be canceled while the `CheckIn` transaction is `Upcoming`, that is, until Swan's check provider receives the check; the exact window depends on postal delays. A canceled check never affects the account balance.

## Settlement date and booked time {#settlement}

Checks are booked 2 to 3 business days after they arrive at Swan's check provider.

## FNCI and verifying checks {#fnci}

Swan verifies every check against the Banque de France's National Irregular Check Register (FNCI) and returns a color code, check payment counters, and the issuing bank.
Refer to [French check verification (FNCI)](/payments/concepts/merchants/fnci) for the results and what to do with them.

## R-transactions {#r-transactions}

For checks, <Term id="r-transaction">R-transactions</Term> are rejections and returns.

### Rejected {#rejected}

Swan's check provider rejects a check and **mails it back** to the account holder's address, with the reason, so the merchant can fix and resend it.

A rejected or canceled check can be declared again: **create a new `CheckIn` transaction before resending it**. A check resent without a new `CheckIn` stays rejected and is mailed back again.

Additionally, all checks not received by Swan's check provider within 30 days of being declared will be automatically `Rejected`.

The [check rejection reasons](/payments/reference/merchant-rejection-reasons#checks-rejected) list each code and the resolution to share with your merchant.

### Returned {#returned}

Checks can be returned up to 10 business days after the transaction is `Booked`, and this window can be extended to 90 calendar days based on the reason for return.
Checks aren't mailed back to the merchant.

The [check return reasons](/payments/reference/merchant-rejection-reasons#checks-returned) list each code.

Because the merchant's account was already credited, Swan automatically creates a `CheckInReturn` transaction that debits it; the original `CheckIn` stays `Booked`.
