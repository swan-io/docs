## The onboarding model {#overview}

For the onboarding model (its types and purpose, plus the [statuses](/accounts/concepts/onboarding/statuses) and [notifications](/accounts/concepts/onboarding/notifications) that span every onboarding), see the [onboarding concept](/accounts/concepts/onboarding). The guides in this section cover each operational task.

## Country requirements {#country-reqs}

Onboarding is a **highly localized experience**.
Everything from **what to include in your API request** to how to ask **users to verify their identity** to whether Swan **requires certain ID numbers or documents** depends on the [account country](/accounts/concepts/account/country).

Account onboarding country requirements are described in the [individual](/accounts/guides/onboarding/individual/requirements#country-reqs) and [company](/accounts/guides/onboarding/company/requirements#country-reqs) onboarding sections.
Follow the requirements for your target countries closely.

## Onboarding links {#links}

You can **generate unique links** using the **API**, or use **public links** from your **Dashboard**.
Learn how to generate onboarding links — including single-use behavior and the `state` parameter — in the guides for [individuals](/accounts/guides/onboarding/individual/create) and [companies](/accounts/guides/onboarding/company/create).

:::info New onboarding API
Swan has released a new version of the onboarding API.
New mutations use a nested input structure and return typed responses (`IndividualAccountHolderOnboarding` or `CompanyAccountHolderOnboarding`).
<DeprecationTimeline />
All guides on this site now present the new API as the primary option.
Follow the [migration guide](/accounts/guides/onboarding/migrate-api) for step-by-step instructions.
:::
