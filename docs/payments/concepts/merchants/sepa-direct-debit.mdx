## Direct debit payments {#payments}

Merchant direct debit payments follow the shared [merchant payment object](/payments/concepts/merchants/payments): one payment groups one or more <Term id="transactions">transactions</Term>, with [statuses](/payments/concepts/merchants/statuses#payments-statuses) and [balances](/payments/concepts/merchants/payments#balances) common to all payment methods.

### Payment object statuses {#payments-statuses}

SEPA Direct Debit payments never use the `Authorized` status: from `Initiated`, a payment is `Captured`, `Rejected`, or `Canceled`, and a `Captured` payment can still be `Refunded` by the merchant or `Disputed` by the customer. Refunds and disputes cover the full amount. The [merchant statuses](/payments/concepts/merchants/statuses#payments-statuses) page has the diagram and definitions.

### Payment object balances {#payments-balances}

The balances used for SEPA Direct Debit payments are `availableToCancel`, `totalCanceled`, `totalCaptured`, `availableToRefund`, `totalRefunded`, and `totalDisputed`. For SEPA Direct Debit, `availableToCancel` is the pending amount that can still be canceled: cancelations must be requested by the day before the scheduled execution and within the [cutoff time](#canceling). The [merchant payments](/payments/concepts/merchants/payments#balances) page defines each balance.

## Schemes: Core and B2B {#schemes}

Swan offers two SEPA Direct Debit schemes: `Core` and `B2B`.
You can choose to use one or both schemes according to your use case.

The [SEPA Direct Debit scheme table](/payments/reference/schemes#sdd) compares eligible account types, refunds, returns, mandate requirements, and timelines for Core and B2B.

## SEPA Creditor Identifier (SCI) {#sci}

SEPA Creditor Identifiers (SCIs) are unique reference codes that identify each creditor participating in a SEPA Direct Debit scheme.
These identifiers are unique to each merchant and help banks sort transactions by merchant to ensure those transactions are routed correctly.

SCIs are composed of several elements, including:

1. ISO two-letter country code
1. Two-digit checksum
1. Creditor business activity code
1. National identification feature

For example, `FR12ABC0123456789` is an SCI from France (`FR`) with the check number `12`, and the business activity code `ABC`, ending with the national identification feature that changes country to country (`0123456789`).

### SCI options {#sci-options}

Swan provides an SCI, and merchants can also choose to use their own.

Both meet all SCI requirements.
It's important to note, however, that **Swan's provided SCI always mentions Swan**, which appears on a user's transaction history.

Merchants might prefer to **use their own SCI for a more customized user experience**.
Users would see the merchant's name instead of Swan on their transaction history, **reducing friction** and the risk of transactions looking suspicious to users.
The merchant's bank would also see the label Swan in disputes, so having the merchant name appear instead could also **ease bank relations**.

Merchants can **change their SCI** from Swan's to a personal SCI.
[Update their profile](/payments/guides/merchants/online/sdd/update) by calling the `requestMerchantPaymentMethodsUpdate` mutation.

Regardless of the type of SCI, it's good practice to **include your merchant's name** in the `label` field for all SEPA Direct Debit transactions.

:::note Personal SCI
If a merchant in France expresses interest in using their own SCI but they don't have one, Swan can help them get their identifier.
Open a support request with Swan to start the process.
:::

## Rolling reserve {#rolling-reserve}

[Rolling reserve](/payments/concepts/merchants/payments#rolling-reserve) applies to SEPA Direct Debit. By default, the Core scheme's reserve is determined by a <Term id="merchant-profile">merchant profile</Term> risk assessment, and the B2B scheme holds 100% of the payment over 3 business days.

## Payment amount limit {#payment-limit}

Swan may apply a [payment amount limit](/payments/concepts/merchants/payments#payment-limit) to a single SEPA Direct Debit (SDD) payment. If a payment exceeds this limit, the API returns a `ForbiddenRejection` error. To query the limit, use the `paymentAmountLimit` field at the `merchantPaymentMethod` level when you [request the payment method](/payments/guides/merchants/online/sdd/request).

## Canceling payments {#canceling}

Merchants can cancel SEPA Direct Debit payments using the [`cancelMerchantPayment`](https://api-reference.swan.io/mutations/cancel-merchant-payment/) mutation.
To understand if a payment is cancelable, check its `availableToCancel` balance.
Only the full amount can be canceled.

Payments can only be canceled before transactions are sent to the SEPA payment gateway, respecting the current cutoff times:

- **SDD Core**: Payments can be canceled until approximately **11:00 Central European [Summer] Time (CET/CEST)**
- **SDD B2B**: Payments can be canceled until approximately **10:00 Central European [Summer] Time (CET/CEST)**

After these cutoff times, the payment can't be canceled and will proceed to settlement.

## Payment mandates {#mandates}

<Term id="payment-mandates">Payment mandates</Term> are mandatory for all SEPA Direct Debit transactions, and you must declare them to Swan.
Refer to [merchant payment mandates](/payments/concepts/merchants/mandates#sdd) for declaring mandates, the required information, and one-off mandates.

## R-transactions {#r-transactions}

:::caution R-transaction availability
Refunds are only possible with **SDD Core** and can be requested up to 8 calendar weeks after due date and time.
Returns are possible for **both** SDD Core and SDD B2B.
:::

### Rejected {#rejected}

When an SDD transaction is **rejected**, the debtor's account is not debited.

The [SEPA Direct Debit reasons](/payments/reference/merchant-rejection-reasons#sdd) list each code and the resolution to share with your merchant.

When an SDD transaction is rejected, regardless of the reason, the merchant receives a notification and can attempt a new SDD at a later date.

### Returned {#returned}

When an SDD transaction is **returned**, the debtor's account is debited the amount, but the payment is reversed and the funds return to the debtor's account. The original transaction stays `Booked`; Swan creates a new return transaction that debits the merchant's account.

The [same reasons](/payments/reference/merchant-rejection-reasons#sdd) apply to returns.

When an SDD transaction is returned, regardless of the reason, the merchant is notified about the return.
They can investigate the reason for return and take whatever action is necessary, which might be refunding the payment or disputing the return with the debtor's bank.
